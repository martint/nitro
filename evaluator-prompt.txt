Implement an expression evaluator as a generalization of the ProjectOperator. Here are the requirements:
* The evaluator should be initialized to handle multiple expressions.
* The expressions compute results over vectors of input values
* The source input vectors should be accessible by ordinal, via an Input interface (which will be implemented by the caller who initializes the evaluator)
* The results of each expression are store into intermediate vectors that are tracked by the evaluator. The input to a function can be either a source input vector or an intermediate vector. Complex function invocation graphs can be modeled by using the intermediate vectors.
* Evaluation should be lazy -- it should be done in response to the caller invoking an evaluate() method with an ordinal that represents the output vector to be returned
* If a function evaluation already computed an intermediate vector needed for another function evaluation, it should not be re-evaluated.
* An evaluation is conditioned by a mask. The lazy computation check should consider the mask to decide whether the underlying expression has been satisfied for the requested mask.
* Evaluation of an expression should be additive in this manner: calling evaluator.evaluate(1, mask1) followed by evaluator.evaluate(1, mask2) should result in only the positions in mask2 that are not already in mask1 being evaluated
* Don't use bitsets for the masks. Use (and extend) the Mask class as necessary to represent the required concepts (intersection, union, difference, etc)
* The evaluator should also be able to handle conditional expressions (e.g., if), which may require computing a mask based on some criteria and then calculating the output as the union of the results of multiple expressions evaluated on non-overlapping regions of the input positions. For example, given a function that computes "if", with a condition, an if-true and an if-false expressions, it needs to be able to compute a mask to determine the true values. Then if needs to compute the if-true expression for the values that satisfy the condition and record them in the output vector. Finally, it needs to compute the if-false expression for the values that do not satisfy the condition and overlay them on the output vector.
* The evaluator should not be directly aware of the existence of conditional expressions. That should be hidden inside the implementation of specific functions. However, there has to be a way for the evaluator to dispatch to the function implementation and for the function to request the evaluation of its inputs given the required masks
* No need to have a dedicated ExtendedFunction class. That should be a common protocol for all function evaluations, regardless of whether they need to implement conditional logic such as "if". For example, for an "add" function, the implementation would just call back into the evaluator asking for it's inputs to be evaluated with the mask that was passed in
