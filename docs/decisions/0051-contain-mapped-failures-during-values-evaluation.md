# ADR-0051: Contain mapped failures during VALUES-only evaluation

- **Status:** accepted
- **Date:** 2026-09-03
- **Spec:** §6, §8
- **Depends on:** [ADR-0008](0008-use-first-class-masks-and-streams.md), [ADR-0012](0012-execute-over-encoded-domains.md), [ADR-0049](0049-exclude-invalid-rows-from-fallible-scalars.md), [ADR-0050](0050-map-declared-scalar-failures-at-the-provider-boundary.md)

## Context

Nitro can demand VALUES and ERRORS from one expression in separate evaluator invocations. A generated fallible
scalar formerly installed its failure handler only when the current invocation requested ERRORS. That is unsafe for
VALUES-only evaluation: a selected row failure escaped instead of remaining row-local. It is also unsafe for
encoded-domain execution, where a compact physical domain can include values that no active logical row observes.

The handwritten Trino VARCHAR-to-BIGINT adapter happened to contain those failures even when ERRORS was not requested.
Replacing it with the otherwise equivalent generated cast made Engine Coverage q09 evaluate an intentionally invalid
inactive branch value as a query failure. Keeping that semantic difference in a function-specific adapter would make
the generic calling convention incomplete.

## Decision

When a fallible generated target has a provider failure mapper and the invocation executes the target, it allocates
or reuses invocation-local error scratch even for VALUES-only demand. Generated bytecode records mapped target
failures there and continues. The adapter releases the scratch before returning and does not publish an unrequested
ERRORS stream. A separate ERRORS invocation remains responsible for returning observable diagnostics.

Fallible generated targets do not use the RLE result shortcut until that shortcut can preserve the same failure
semantics. Targets without a failure mapper continue to throw, and failures outside the protected scalar invocation
continue to escape.

## Consequences

- Generated and native batch implementations obey the same independently demanded stream semantics.
- An inactive physical-domain value cannot make a conditional expression fail merely because its dictionary remains
  visible during VALUES evaluation.
- The exceptional convention pays one pooled error scratch vector per active invocation. The allocation remains
  bounded by the physical evaluation domain and is reusable; it does not retain host exceptions or row objects.
- The handwritten VARCHAR-to-BIGINT cast adapter can be removed in favor of the registry-resolved generated cast.

## Alternatives considered

**Always request and publish ERRORS with VALUES.** This violates independent stream demand and forces downstream
consumers to carry a stream they did not request.

**Let VALUES evaluation throw and rely on branch masks.** This fails for encoded domains containing inactive values
and makes the outcome depend on physical representation.

**Keep a function-specific adapter.** This duplicates a general calling-convention responsibility and leaves every
other fallible registry function exposed to the same defect.
