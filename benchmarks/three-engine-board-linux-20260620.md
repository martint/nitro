# Nitro vs Velox vs Trino — three-engine board (2026-06-20)

Single-thread, apples-to-apples (same operator/plan shape per query), Linux box. Nitro = interpreted
operator tree (dynamic-filter + skip-decode ON by default). All engines read the **same** parquet files
(`/root/data`, sf10 TPC-H/TPC-DS, full 14 GB ClickBench). Velox pinned `--num_drivers=1 --num_io_threads=1
--num_splits_per_file=1`, memory-capped `--cache_gb=12` + 14.5 GB RSS watchdog. Nitro/Trino JMH `-wi 3 -i 4
-f 1`, `-Xmx12g`; Velox min-of-3 `run_query_verbose`. **Ratio > 1 ⇒ Nitro slower than that engine.**
